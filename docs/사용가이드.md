# 사용 가이드

어댑터는 **학습 때와 같은 입력 형식** 으로 써야 결과표의 성능이 나옵니다. 이 문서는 그 형식을 정리합니다.
실행 예제는 [`examples/infer.py`](../examples/infer.py) 에 있습니다.

---

## 1. 어댑터 고르기

| 어댑터 | 원본 모델 | 용도 |
|---|---|---|
| `adapters/E2B/multi` | `google/gemma-4-E2B-it` | **권장.** 8과제 통합 (`answerfull` 제외 · 응답생성은 `answer` 틀) |
| `adapters/E2B/<과제>` | `google/gemma-4-E2B-it` | 과제 하나만 쓸 때, 또는 통합 어댑터와 비교할 때 |
| `adapters/E4B/<과제>` | `google/gemma-4-E4B-it` | E4B 를 이미 쓰고 있을 때. 성능은 E2B 와 같습니다 |

- 어댑터는 **학습한 원본 모델에만** 붙습니다. E2B 어댑터를 E4B 나 다른 모델에 붙이면 안 됩니다.
- `adapter_config.json` 의 `base_model_name_or_path` · `revision` 이 학습에 쓴 원본 모델입니다.
- 설정: LoRA r=16 · α=32 · dropout 0.05 · 대상 층 `model.language_model.layers.N.self_attn.{q,k,v,o}_proj`.

---

## 2. 메시지 구성

- **사용자 메시지 1개만** 보냅니다. 시스템 메시지는 쓰지 않습니다.
- 원본 모델의 채팅 템플릿을 `add_generation_prompt=True` 로 적용합니다. 생각(thinking) 모드는 켜지 않습니다.
- 사용자 메시지 = 과제 프롬프트 틀(`prompts/<과제>.txt`, 끝 줄바꿈 제거)의 `{자리표시자}` 를 입력값으로 바꾼 것.
- 분류 과제에도 **라벨 목록을 프롬프트에 넣지 않습니다.** 어댑터가 라벨을 이미 배웠습니다.

---

## 3. 과제별 프롬프트 틀

| 과제 | 틀 | 자리표시자 |
|---|---|---|
| 카테고리분류 | `prompts/category.txt` | `{question}` = 고객의 첫 요청 한 문장 |
| 고객의도분류 | `prompts/intent.txt` | `{context}` = 직전 발화 (`상담사: …`) · `{question}` = 고객 발화 |
| 통화전체분류 | `prompts/callcat.txt` | `{transcript}` = 통화 전체 |
| 핵심어추출 | `prompts/keyword.txt` | `{question}` = 발화 1개 |
| 슬롯추출 | `prompts/slot.txt` | `{context}` = 직전 발화 · `{question}` = 고객 발화 |
| 상담사행동 | `prompts/action.txt` | `{transcript}` = 지금까지의 통화 |
| 고객응답생성 | `prompts/custreply.txt` | `{transcript}` = 지금까지의 통화 |
| 응답생성 | `prompts/answer.txt` (`answerfull` 도 같은 틀) | `{transcript}` = 지금까지의 통화 |

**통화 내용(`{transcript}`) 형식**

- 한 줄에 발화 1개 · `상담사: ` 또는 `고객: ` 로 시작 · 줄바꿈(`\n`)으로 잇습니다.
- 학습 최대 길이는 4,096 토큰(입력 + 출력)입니다. 더 긴 통화는 학습에서 본 적이 없습니다.

**예 — 응답생성 사용자 메시지** (아래 통화는 설명용으로 만든 예입니다)

```
쇼핑몰 고객센터 상담사로서, 아래 통화에 이어질 상담사의 다음 발화 한 마디를 작성하시오.

통화 내용:
상담사: 안녕하세요, 고객센터입니다.
고객: 주문한 가방이 아직 안 와서요.
```

**예 — 고객의도분류 사용자 메시지**

```
다음 쇼핑몰 고객센터 통화에서 고객 발화의 의도를 분류하시오.

직전 발화: 상담사: 어떤 점이 불편하셨을까요?
고객 발화: 받은 셔츠 단추가 떨어져 있어서요.
```

## 4. 생성 설정

결과표의 모든 수치는 아래 조건에서 냈습니다.

- **greedy** (샘플링 없음 · temperature 0).
- 정지 토큰 = 원본 모델 `generation_config` 의 eos ∪ 토크나이저 eos ∪ 턴 종료 토큰 `<turn|>`.
- **반복 페널티는 쓰지 않았습니다.**

| 과제 | 학습본 실제 출력 길이 (통합 어댑터) | 권장 생성 상한 |
|---|---|---|
| 분류 4과제 | 2~9자 (라벨 이름) | 32 토큰 |
| 핵심어추출 | 최대 60자 | 256 토큰 |
| 슬롯추출 | 최대 47자 | 128 토큰 |
| 고객응답생성 | 중앙값 8자 · 최대 22자 | 256 토큰 |
| 응답생성 | 중앙값 27자 · 정상 답 최대 77자 | 256 토큰 |

- 생성 과제 상한 256 토큰은 학습 정답의 최장(약 200자)을 덮는 값입니다.
- **상한에 닿아 정지 토큰 없이 끝난 답은 반복 루프로 보고 버리거나 다시 시도** 하세요. 생성 과제 100건 중 0~4건에서 끝나지 않는 반복이 나왔습니다 (대부분 가림 문자 `ㅇㅇㅇㅇ` 반복).
- 반복 페널티를 켜면 루프는 줄겠지만 정상 답의 품질도 달라질 수 있습니다 (평가하지 않음). 분류·추출 과제에는 쓰지 마세요.

## 5. 출력 처리

| 과제 | 출력 형식 | 처리 |
|---|---|---|
| 분류 4과제 | 라벨 이름 1개 (예: `반품`, `사이즈·색상교환`) | `labels/<과제>.labels.txt` 와 정확히 비교 |
| 핵심어추출 | 한 줄에 핵심어 1개 · 없으면 `없음` | 줄 단위로 나눔 |
| 슬롯추출 | 한 줄에 `항목이름: 값` · 없으면 `없음` · 같은 항목이 여러 줄일 수 있음 | 첫 `: ` 기준으로 나눔. 항목 이름은 프롬프트의 19개 중 하나 |
| 생성 2과제 | 발화 한 마디 (따옴표·화자 표시 없음) | 그대로 사용 · 상한에 닿으면 버림 |

라벨: `category` · `callcat` = 교환/반품/배송 · `intent` 15종 · `action` 16종.

---

## 6. 주의점

1. **응답생성은 조회 값을 지어냅니다.** 학습 정답이 상담사가 조회 화면을 보고 한 말이라, 통화에 없는 상품명·주문일·주소·금액을 말합니다. 고객에게 바로 내보내지 말고 상담사 보조 초안으로만 쓰세요. 근본 해결은 조회 결과를 입력에 넣는 구조(RAG·도구 호출)로 다시 학습하는 것입니다.
2. **상담사행동 상한은 약 66%** 입니다. 추천 후보로 보여 주고 사람이 고르게 하세요.
3. **카테고리분류는 첫 문장만 봅니다** (85%). 통화가 끝난 뒤라면 통화전체분류(96%)를 쓰세요.
4. **학습 데이터는 이름·전화번호·주소가 `ㅇ` 으로 가려져 있습니다.** 실제 서비스 입력에는 진짜 값이 들어오므로 분포가 다릅니다.
   - 슬롯추출은 "발화에 적힌 그대로" 를 배웠으므로 실제 값도 뽑을 것으로 예상하지만 확인하지 않았습니다.
   - 생성 과제는 가림 문자를 흉내 냅니다 (`ㅇㅇ쇼핑`, `ㅇㅇㅇ 고객님`). 후처리하거나 초안으로만 쓰세요.

## 7. 서빙 (vLLM 등)

- 학습·평가는 **transformers + PEFT** 로만 했습니다. vLLM 등 서빙 엔진에서는 확인하지 않았습니다.
- 서빙 엔진의 LoRA 기능으로 원본 모델 1개에 어댑터를 붙여 쓸 수 있으면, 위 형식 그대로 요청하면 됩니다. 쓰기 전에 아래로 결과가 같은지 확인하세요.
  - 같은 입력 몇십 건을 transformers + PEFT(`examples/infer.py`)와 서빙 엔진에 greedy 로 보내 출력을 비교합니다.
  - 어댑터가 붙지 않으면 원본 성능(예: 카테고리분류 76.7%)이 나옵니다.
- 서빙 엔진이 이 어댑터를 지원하지 않으면 PEFT `merge_and_unload()` 로 원본에 합친 완결 모델을 만들어 올릴 수 있습니다 (이 방법도 확인하지 않았습니다).
