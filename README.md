# Gemma-4 쇼핑 상담 LoRA 어댑터

쇼핑몰 고객센터(교환·반품·배송) 통화 데이터로 학습한 **Gemma-4 E2B · E4B LoRA 어댑터 19개** 입니다.
분류 4종 · 추출 2종 · 생성 3종, 모두 9개 과제를 다룹니다.

LoRA adapters for Gemma-4 E2B / E4B, fine-tuned on Korean shopping call-center conversations (exchange, return, delivery): 4 classification, 2 extraction and 3 generation tasks.

- 원본 모델: [`google/gemma-4-E2B-it`](https://huggingface.co/google/gemma-4-E2B-it) · [`google/gemma-4-E4B-it`](https://huggingface.co/google/gemma-4-E4B-it) (Apache 2.0)
- 학습 데이터: AI Hub 「민원(콜센터) 질의-응답 데이터」 K쇼핑 분야 중 교환·반품·배송 ([출처](#출처--라이선스))
- 학습 방식: LoRA r=16 · α=32 · attention 층(q/k/v/o)만 · 학습률 2e-4 · 유효 배치 16

> 이 저장소에는 **어댑터 가중치 · 프롬프트 틀 · 라벨 목록 · 사용법 · 결과 요약** 만 있습니다. 학습 데이터 원문은 들어 있지 않습니다.

---

## 어떤 어댑터를 쓰면 되나

**`adapters/E2B/multi` 하나면 됩니다.** 8개 과제를 어댑터 1개(21.5MB)로 처리하고, 과제별 어댑터보다 성능이 낮지 않습니다.

| 과제 | 입력 → 출력 | 통합 `E2B/multi` | 과제별 `E2B/<과제>` | 과제별 `E4B/<과제>` | 원본 E2B (학습 전) |
|---|---|---|---|---|---|
| `category` 카테고리분류 | 고객의 첫 요청 → 교환/반품/배송 | 85.0% | 85.4% | 85.5% | 76.7% |
| `intent` 고객의도분류 (15종) | 직전 발화 + 고객 발화 → 의도 | 81.6% | 81.5% | 81.6% | 61.9% |
| `callcat` 통화전체분류 | 통화 전체 → 교환/반품/배송 | 96.4% | 96.2% | 96.4% | 94.2% |
| `keyword` 핵심어추출 | 발화 → 핵심어 목록 | F1 0.943 | 0.940 | 0.943 | 0.505 |
| `slot` 슬롯추출 (19항목) | 고객 발화 → `항목: 값` | F1 0.943 | 0.947 | 0.938 | 0.340 |
| `action` 상담사행동 (16종) | 통화 이력 → 다음 상담사 행동 | **66.1%** | 64.2% | 65.7% | 22.7% |
| `custreply` 고객응답생성 | 통화 이력 → 다음 고객 발화 | 승률 98.0% | 95.0% | 71.5% | — |
| `answer` 응답생성 | 통화 이력 → 다음 상담사 발화 | 승률 78.0% | 77.5% | 68.5% | — |
| `answerfull` 응답생성 (전량 학습) | (위와 같음) | — | 80.5% | 71.5% | — |

- 분류는 정확도, 추출은 micro F1, 생성은 **같은 크기 원본 모델 대비 블라인드 쌍 판정 승률** (50% = 동등) 입니다. 생성 승률은 원본이 형식을 지키지 못한 경우에 크게 좌우되므로 E2B와 E4B를 이 값으로 비교하지 마세요.
- `answer` 는 2만 건, `answerfull` 은 13.3만 건으로 학습했습니다. 둘을 직접 비교한 판정에서 차이가 없었습니다. `answer` 를 권장합니다.
- E4B는 E2B보다 크지만 학습 후 성능은 같습니다. 12B · 26B-A4B · 31B 도 학습했지만 역시 결과가 같아 어댑터는 공개하지 않았습니다. 다섯 크기 전체 결과는 [docs/결과요약.md](docs/결과요약.md) 에 있습니다.

## 빠른 시작

```bash
pip install "transformers>=5.8,<5.15" "peft>=0.21" accelerate torch
```

> Gemma-4 는 transformers 5.15 이상에서 로드 오류가 납니다. 학습은 transformers 5.14.1 · PEFT 0.21.2 로 했습니다.

```bash
# 카테고리분류
python examples/infer.py --adapter adapters/E2B/multi --task category \
  --question "지난주에 받은 신발이 작아서 다른 사이즈로 바꾸고 싶어요."

# 응답생성 (통화 내용은 한 줄에 발화 1개, "상담사: " / "고객: " 로 시작)
python examples/infer.py --adapter adapters/E2B/multi --task answer \
  --transcript "상담사: 안녕하세요, 고객센터입니다.
고객: 주문한 가방이 아직 안 와서요."
```

원본 모델은 `adapter_config.json` 에 적힌 Hugging Face 저장소·revision 에서 자동으로 받습니다.

**입력 형식이 학습 때와 다르면 성능이 떨어집니다.** 과제별 프롬프트 틀, 자리표시자, 생성 설정, 출력 처리는 [docs/사용가이드.md](docs/사용가이드.md) 를 보세요.

## 저장소 구성

```
adapters/
  E2B/multi/            통합 어댑터 (8과제, 권장)
  E2B/<과제>/           과제별 어댑터 9개
  E4B/<과제>/           과제별 어댑터 9개
prompts/<과제>.txt      과제별 프롬프트 틀 (학습 때 쓴 원문 그대로)
labels/<과제>.labels.txt 분류 과제 라벨 목록
docs/사용가이드.md      입력 형식 · 생성 설정 · 출력 처리 · 주의점
docs/결과요약.md        실험 방법 · 5개 크기 전체 결과 · 추가 실험
examples/infer.py       transformers + PEFT 추론 예제
SHA256SUMS.txt          어댑터 파일 해시
```

각 어댑터 폴더에는 `adapter_config.json` 과 `adapter_model.safetensors` 만 있습니다 (E2B 21.5MB · E4B 36.3MB).

## 알려진 한계

- **응답생성은 조회 값을 지어냅니다.** 학습 정답이 상담사가 주문 조회 화면을 보고 한 말이라, 통화에 없는 상품명·주문일·주소를 그럴듯하게 말합니다 (100건 중 4~8쌍). 모델 크기를 키워도, 데이터를 늘려도 줄지 않았습니다. 고객에게 바로 내보내지 말고 상담사 보조 초안으로만 쓰세요.
- **상담사행동은 약 66%가 상한입니다.** 같은 통화 이력에서도 다음 행동이 하나로 정해지지 않기 때문입니다. 추천 후보로 쓰세요.
- **학습 데이터의 개인정보는 가림 문자 `ㅇ` 으로 되어 있습니다.** 생성 과제는 이 문자를 흉내 내고(`ㅇㅇ쇼핑`), 드물게 `ㅇㅇㅇㅇ…` 를 끝없이 반복합니다. 생성 상한을 꼭 두세요.
- 생성 과제 판정은 LLM 1명이 고정 기준으로 블라인드 판정했고, 평가셋이 100건입니다. 사람 검수는 하지 않았습니다.
- 모든 결과는 단일 시드(42) · 1회 학습 값입니다.
